SOC Analyst Toolbox

A fully local, privacy-first threat intelligence workbench for SOC analysts. Paste any IOC — IP address, domain, URL, file hash, email address, CVE — and immediately pivot across 30 enrichment providers, 14 structured investigation workflows, and 61 curated OSINT tool links. Nothing is sent to any cloud service except the provider APIs you explicitly configure.

30 enrichment providers 14 investigation workflows 61 curated OSINT tools 11 IOC types supported ✓ Local only · No telemetry
The Problem

SOC analysts spend a significant portion of their triage time context-switching — opening 8–12 browser tabs, re-entering the same IOC into different tools, waiting for results, and then manually correlating what they find. There is no standardised process, no shared context, and no memory between investigations.

⏱
Investigation time
Analysts lose 5–15 minutes per IOC navigating between disparate tools and re-entering the same indicator.
🔀
No standardisation
Different analysts use different tools in different orders, producing inconsistent coverage and missed context.
🔐
Data privacy risk
Pasting live IOCs into cloud-based tools may expose sensitive indicators to third-party services without analyst awareness.
What It Is

The SOC Analyst Toolbox is a single-page application running entirely on the analyst's local machine. The analyst pastes an IOC into the search bar; the tool auto-detects the type, presents the relevant investigation workflows, and with one click fans out to all appropriate enrichment providers simultaneously. Results stream back in real time — severity-rated, key-fact-extracted, contradiction-flagged, and ready to pivot.

Paste once, query everywhere. One IOC entry fans out to up to 30 enrichment providers concurrently. No manual re-entry.
Structured workflows enforce process. 14 pre-built investigation workflows map directly to common SOC use cases — IP triage, phishing, malware hash, email header review, ransomware context, and more. Each workflow provides a curated checklist.
AI narrative synthesis. An optional local AI model (Ollama, running on-device) synthesises all enrichment results into a plain-English analyst verdict with cited sources and recommended actions. No data leaves the machine.
Pivot without losing context. Resolved IPs, certificate SANs, and related domains appear as clickable chips that immediately load into the investigation panel for chained analysis.

How It Works — Architecture
1
IOC Input & Type Detection
The analyst pastes an IOC. The frontend applies regex-based detection to classify it as IPv4, IPv6, domain, URL, MD5, SHA1, SHA256, email, ASN, CIDR, or CVE. Defanged formats (hxxps://, 1[.]2[.]3[.]4, zero-width Unicode characters) are automatically normalised.
2
Workflow Selection
The analyst selects a workflow (e.g. IP Triage, Domain Triage, Malware Hash). Each workflow defines which enrichment providers to query and presents a context-specific investigation checklist and internal search templates.
3
Concurrent Enrichment (local backend)
The React frontend sends a single POST request to the local Node.js/Express backend on localhost. The backend fans out to all configured providers simultaneously using Promise.allSettled. Each provider adapter has independent timeout handling so a slow or unavailable provider never blocks the rest.
4
Caching
Results are cached in-memory with per-provider TTLs (10 minutes for DNS up to 24 hours for WHOIS). Repeated lookups for the same IOC are served instantly without burning API rate limits or quota. Cache can be bypassed with an explicit force-refresh.
5
Severity Scoring & Contradiction Detection
The backend computes overall severity from active (non-passive) sources. Passive/contextual providers (DNS, WHOIS, ip-api, BGPView) are excluded from severity scoring to avoid inflating results. A contradiction engine flags conflicts: benign vs. malicious classifications, low-corroboration VT detections, and domain age mismatches.
6
AI Narrative (optional)
The backend calls a locally running Ollama LLM with a structured prompt containing all enrichment results. The model produces a structured verdict with cited sources, key findings, recommended actions, and analyst notes. If citation density is low, the backend auto-retries with an enforcement prompt.
7
Results Rendered
The frontend displays the auto-analysis panel (verdict, confidence meter, key findings, recommended actions, enrichment source breakdown), the provider-by-provider results panel, and pivot chips for resolved IPs and related domains — all in a single view.
🏗
Architecture summary
Frontend (React 18 + TypeScript + Vite, running on localhost:5173) communicates exclusively with Local Backend (Node.js + Express + TypeScript, running on localhost:8787). The backend makes outbound API calls to configured threat intel providers. API keys are stored in a local .env file, never exposed to the browser. The AI model (Ollama) runs on the same machine. No data is ever routed through any cloud intermediary.

Privacy & Security Model
🔒
Zero cloud infrastructure. All data stays local.
The toolbox runs entirely on the analyst's machine. No SaaS, no shared backend, no analytics, no telemetry. The only outbound connections are to the enrichment provider APIs you configure — and only when you explicitly trigger a lookup.
🔑 API key isolation
API keys are stored in a local .env file on the analyst's machine. The React frontend never receives or handles keys — all provider calls go through the local backend. Keys are never logged or transmitted.
🤖 Local AI processing
AI narrative generation uses Ollama, a locally-running LLM. The enrichment data, IOC, and prompt are processed entirely on-device. No data is sent to OpenAI, Anthropic, or any cloud AI service.
🌐 Controlled outbound calls
Outbound API calls are made only when the analyst runs enrichment. Passive providers (DNS, WHOIS, RIPE) perform read-only lookups. Submitting IOCs to providers is clearly labelled — tool links marked "Submits IOC" warn before use.
💾 Local storage only
Search history, API keys, and configuration are stored in localStorage and a local .env file on the analyst's machine. There is no database, no cloud sync, and no shared session state.

Getting Started
1 — Start the backend
cd backend
npm install
npm run dev
Starts on localhost:8787. The frontend health-checks every 30 seconds and shows online/offline status.
2 — Start the frontend
npm install
npm run dev
Opens at localhost:5173. Single-page app — no build step needed during development.
3 — Configure API keys
Open the API Keys tab in the UI and paste credentials. Saved immediately to backend/.env. No restart required. Free keys for GreyNoise, VirusTotal, AbuseIPDB, OTX, ThreatFox, URLhaus, urlscan.io, and Pulsedive are sufficient for most investigations.
4 — Enable AI analysis (optional)
ollama pull qwen2.5
Install Ollama and pull any model. The backend auto-detects running models. qwen2.5 (4GB) produces strong structured analysis. Any Ollama-compatible model works.
